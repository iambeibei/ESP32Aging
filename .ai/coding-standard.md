## 头文件

### 头文件只放接口声明

要求：头文件只放对外接口声明、必要类型、必要宏和必要 `static inline`，不得放普通函数实现、变量定义或内部 helper 声明。

检查：新增 `.h` 文件时检查是否分配存储、暴露内部细节、定义普通函数体。

### 头文件必须自包含

要求：公共头文件应能被单独 include 编译，自己包含所需依赖，并使用 include guard 或 `#pragma once`。

检查：头文件中使用 `uint32_t`、结构体、枚举、宏时，确认依赖来自本文件 include，而不是调用方 include 顺序。

### 禁止头文件循环依赖

要求：头文件依赖保持单向；跨模块依赖优先使用前置声明或拆分公共类型。

检查：新增 include 时检查是否形成 A 包含 B、B 又间接包含 A 的循环。

## 函数

### 函数职责单一

要求：一个函数只完成一个明确职责。初始化、配置、校验、启动、错误恢复等阶段应拆分为独立函数。

检查：函数过长、嵌套过深、同时处理多个阶段时，优先拆分。

### 函数调用上下文必须明确

要求：公开函数应说明是否可在 ISR 调用、是否可能阻塞、是否可重入、是否依赖任务上下文。

检查：被 ISR、callback、task 同时调用的函数，必须检查同步和阻塞行为。

### 函数返回值必须处理

要求：返回错误码或状态的函数，调用方必须检查返回值；明确允许忽略时要注释说明。

检查：HAL、RTOS、driver、flash、queue、mutex、IO API 的返回值不得静默丢弃。

## 命名

### 标识符使用统一风格

要求：函数、变量、文件默认 `snake_case`；类型默认 `PascalCase`；宏和枚举常量默认 `UPPER_SNAKE_CASE`。历史模块已有统一风格时，优先保持模块内一致。

检查：新增符号是否与相邻代码风格一致，不混用多套命名体系。

### 全局对象必须表达归属

要求：全局变量必须带模块前缀；能 `static` 的对象必须限制在文件内。

检查：新增全局变量、`extern` 变量、跨文件共享状态时，检查归属、访问约束和注释。

### 单位必须写入名字

要求：时间、长度、频率、计数、地址、tick/byte/word 等单位必须体现在变量名或接口注释中。

检查：避免裸 `len`、`size`、`timeout`，使用 `len_bytes`、`timeout_ms`、`timeout_ticks`、`transfer_words` 等。

## 变量、类型与内存

### 跨边界数据使用定宽类型

要求：协议字段、寄存器值、flash 持久化数据、跨平台数据必须使用 `stdint.h` 定宽类型。

检查：结构体、协议解析、flash 布局、MMIO 操作中不得依赖裸 `int/long` 宽度。

### 变量必须初始化后使用

要求：局部变量、结构体、buffer、状态对象使用前必须初始化；发送到协议、外设、flash、日志或 DMA 的结构体必须完整初始化。

检查：错误路径复用对象、结构体 padding、部分字段初始化、callback context 初始化。

### 指针所有权必须清晰

要求：指针参数必须明确所有权、生命周期、是否可为 `NULL`；只读数据加 `const`。

检查：DMA buffer、异步队列、callback context、跨 task 指针不得引用已失效对象。

### 默认禁止运行期动态内存

要求：默认不在运行期直接使用 `malloc/free/new/delete`。必须使用时要检查失败、说明所有权和释放路径。

检查：异常出口、重试路径、初始化失败路径必须释放已获取资源。

### 栈使用必须可控

要求：不使用递归；避免大数组局部变量；RTOS task 栈大小必须有依据。

检查：局部大 buffer、深调用链、ISR 栈、任务栈余量。

## 宏与常量

### 宏表达式必须安全展开

要求：宏参数和整体表达式必须加括号；多语句宏使用 `do { ... } while (0)`；宏参数不得依赖副作用。

检查：宏调用参数包含 `++`、`--`、函数调用副作用时要避免重复求值。

### 禁止散落魔法数

要求：非显然常量必须使用命名宏、枚举或 `const` 对象，并注明来源。

检查：寄存器值、时序常数、协议 magic、校准参数、clock divider 必须可追溯到 datasheet、协议或实验记录。

## 中断、并发与 RTOS

### ISR 必须短小且不阻塞

要求：ISR 只做取数据、清标志、记录状态、唤醒任务；不得调用阻塞 API、普通 mutex、delay、printf 或非 ISR-safe HAL/RTOS API。

检查：ISR 中出现循环、协议解析、日志输出、复杂状态机、普通 RTOS API 时必须拆分。

### 共享状态必须同步

要求：ISR/task 共享状态必须有同步策略；`volatile` 不能替代原子性、临界区、锁或队列同步。

检查：共享计数器、ready flag、ring buffer head/tail、状态结构体发布顺序。

### RTOS API 必须匹配上下文

要求：ISR 中只能调用明确 ISR-safe 的 API，例如 FreeRTOS `FromISR` 系列；task 中不得忙等。

检查：queue、semaphore、mutex、notification、timer callback 的使用上下文和超时语义。

### 临界区必须短小

要求：临界区内只访问必要共享数据，不调用可能阻塞的 API。可能长时间持有的共享资源使用带优先级继承的 mutex。

检查：锁顺序、持锁调用下层接口、关中断范围、优先级反转风险。

## HAL、寄存器与 DMA

### 外设访问必须经过统一层

要求：应用层不得绕过 HAL/LL/驱动封装直接写寄存器，除非当前模块就是寄存器封装层。

检查：业务代码中的裸寄存器访问、SDK handle 内部字段访问、绕过 HAL 的 shadow state。

### 寄存器位操作必须显式

要求：寄存器位操作使用命名 mask/shift，避免魔法数和不安全 read-modify-write。

检查：W1C、read-to-clear、sticky bit、中断标志清除顺序必须按芯片手册实现。

### 高风险硬件配置必须说明来源

要求：clock、pin mux、DMA、cache、flash、linker、boot 配置改动必须写明理由或来源。

检查：初始化代码、链接脚本、board config、外设 bring-up、低功耗配置。

### DMA buffer 生命周期必须覆盖传输完成

要求：交给 DMA 的 buffer 在传输完成前必须有效；cache clean/invalidate 策略必须明确。

检查：局部栈 buffer、ring buffer 槽位复用、cacheable memory、DMA completion IRQ。

## 错误处理与输入校验

### 错误路径不得为空

要求：错误路径至少记录、计数、上报、降级、复位或返回错误，不得保留空分支。

检查：`if (err) {}`、只注释不处理、总是返回成功、异常出口资源未释放。

### 外部输入必须校验

要求：协议帧、命令参数、传感器读数、flash 数据和外部长度字段必须先校验再使用。

检查：长度、范围、CRC、枚举值、版本、数组索引、整数溢出、符号转换。

### 重试必须有退出条件

要求：retry 必须有上限或退出条件，并区分瞬时故障和持续故障。

检查：无限循环重试、无退避策略、故障恢复后软件状态与硬件状态不同步。

## 测试、诊断与注释

### 业务逻辑应可测试

要求：业务逻辑与硬件访问分离；纯逻辑优先写成可宿主单测的函数。

检查：协议解析、状态机、计算逻辑是否直接调用硬件 API。

### 关键状态应可诊断

要求：关键模块提供必要状态查询、错误计数或诊断信息。

检查：driver state、错误计数、统计信息、调试命令是否足够定位现场问题。

### 注释必须维护真实约束

要求：公开 API 注释必须说明参数、返回值、所有权、调用上下文、是否阻塞、是否 ISR-safe；修改代码时同步更新相关注释。

检查：过时注释、无来源常量、无主 `TODO` / `FIXME`。
